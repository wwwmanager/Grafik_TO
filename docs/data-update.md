# Обновление справочника населённых пунктов

## Как пересобрать один регион

```bash
node scripts/build-settlements.mjs --region <код> --force
```

- `<код>` — числовой код региона (1–95, см. `public/data/regions.json`).
- `--force` — перезаписать существующий файл.

Пример для Челябинской области (74):
```bash
node scripts/build-settlements.mjs --region 74 --force
```

## Как пересобрать все регионы

```bash
node scripts/build-settlements.mjs --all
```

- Пропускает регионы, чьи файлы уже существуют (используйте `--force` для полной пересборки).
- Пауза 5 с между регионами, 2.5 с между муниципалитетами — будьте вежливы к Overpass API.
- При ошибках (429/504/таймаут) — повторные попытки с экспоненциальным бэкоффом.
- Итоговый отчёт: `regions.json` + список неудач (если есть).

## Регулярность

- **Рекомендуемая каденция**: раз в квартал (OSM обновляется ежемесячно, Geofabrik — ежемесячно).
- После пересборки: `npm run verify` → коммит → пуш → GitHub Actions → Pages.

## Лицензия (ODbL)

- Данные из OpenStreetMap распространяются под **ODbL 1.0**.
- Обязательно:
  1. Атрибуция в приложении: `Справочник НП © участники OpenStreetMap (ODbL)` (уже в футере `index.html`).
  2. Файл `public/data/LICENSE-OSM.txt` с полным текстом лицензии (должен быть в репозитории).
  3. Производные JSON-файлы (`settlements/*.json`) коммитятся в репозиторий — это удовлетворяет share-alike.
- Не удаляйте `LICENSE-OSM.txt` и не убирайте атрибуцию из футера.

## Структура выходных данных

```
public/data/
├── regions.json              # индекс всех регионов
├── LICENSE-OSM.txt           # ODbL attribution
└── settlements/
    ├── 1.json                # Респ. Адыгея
    ├── 2.json                # Респ. Алтай
    ...
    ├── 74.json               # Челябинская область
    ...
    └── 95.json               # Краснодарский край
```

- `regions.json`: `[{code, iso, name, file, count, bytes}, ...]` — отсортировано по имени на русском.
- Каждый `settlements/<code>.json`: массив объектов `{name, type, municipality, lat, lon}`, отсортированный по муниципалитету и имени. Минифицированный JSON (без пробелов).
- Лимит файла: 1.5 MB raw. Предупреждение в логе, если превышен.

## Типы населённых пунктов

Включены: `city`, `town`, `village`, `hamlet`.
Исключены: `locality` (урочища, нежилые места) + имена с цифрами, `ур.`/`урочище`, `нежил`.

## Проверка

```bash
npm run test -- tests/settlements-data.test.js
npm run verify
```

Тесты проверяют:
- Схема `regions.json` и существование всех файлов.
- Схему каждого файла региона.
- Отсутствие типа `locality`, дублей (name, municipality, 3-dec coords), мусорных имён.
- Контрольные точки для региона 74 (Сатка/Бердяуш → Саткинский, Тайнак/Тундуш → Златоуст, Тюбук → Каслинский, Магнитка → Кусинский) и наличие крупных городов.
