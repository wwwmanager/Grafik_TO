# Техническое задание: Генератор графика технического осмотра (веб-приложение)

Источник: владелец, 2026-11-23. Авторитетный текст требований; изменения — только через архитектора (L0).

## 1. Цель
Статическое клиентское веб-приложение (HTML/CSS/JS) для GitHub Pages и автономной работы в браузере:
автоматическое формирование годового графика технического осмотра самоходной техники по выгрузке из реестра (Excel).

## 2. Безопасность (Zero Data Leakage)
- Excel содержит персональные данные (ФИО, ИНН, адреса, паспортные данные).
- Вся обработка, расчёты и анализ адресов — строго в браузере.
- Запрещено отправлять данные из Excel наружу, подключать внешнее геокодирование и стороннюю аналитику.
- Единственный допустимый сетевой запрос — производственный календарь РФ по номеру года (без пользовательских данных).

## 3. Стек и архитектура
- Vanilla JS (ES-модули) или Vite + Vanilla JS (сборка в статику для GitHub Pages).
- Чистый CSS с дизайн-токенами (`tokens.css`), без тяжёлых CSS-фреймворков; компактный аккуратный интерфейс.
- Чтение `.xlsx`/`.xls`: SheetJS (`xlsx`). Экспорт оформленного `.xlsx` (границы, шрифты, автоширина): ExcelJS.
- Тесты: Vitest (парсер заголовков, фильтрация, расчёт дат включая А4, группировка, сдвиг дат, распределение по времени).
- Модули: `parser.js`, `calendarService.js`, `scheduler.js`, `exporter.js`, `ui.js`.
- Деплой: GitHub Actions → GitHub Pages + `README.md`.

## 4. Входные данные, парсинг Excel
- Загрузка Drag-and-Drop или кнопкой (`.xlsx`, `.xls`).
- Набор колонок может меняться; поиск строго по названиям заголовков (нормализация пробелов и переносов строк).
- Обязательные: `Владелец`, `Дата ТО` — при отсутствии понятная ошибка.
- Опциональные:
  - Статусы исключения: `Дата снятия`, `Угон`, `Без ТО`, `Сдан ГРЗ`, `Вывезена за рубеж`.
  - Владельцы/география: `ИНН`, `Группа владельца`, `Адрес владельца`.
  - Техника: `Категория`, `Гос. рег. знак`, `Марка`, `Наименование`, `Зав. №`.

## 5. Настройки (панель параметров)
1. Целевой год (по умолчанию текущий + 1).
2. Приёмные дни недели (чекбоксы Пн–Пт) — исключаются из выездного графика.
3. Отпуск инспектора (вкл/выкл + даты «с»/«по») — полностью исключается.
4. Глубина давности ТО, лет (по умолчанию 3) — техника без ТО дольше срока исключается.
5. Окно группировки техники одного владельца, дней (по умолчанию 30).
6. Физлица с ≤ 3 ед. техники: А — исключить полностью; Б — исключить из таблицы, но добавить под таблицей
   примечание о приёме физлиц в приёмные дни по адресу инспекции. Физлица с > 3 ед. всегда в графике.
7. Рабочий день и нагрузка: начало/конец (09:00–18:00); «Учитывать обед» + интервал (12:00–13:00);
   машин в час на площадке (12, диапазон 10–15); переезд между разными локациями, мин (60).

## 6. Алгоритм
### Шаг 1. Фильтрация (с причиной для листа аудита)
Исключить, если: заполнена `Дата снятия`; непустое/положительное значение (`Да`, `1`, `True`, дата и т.п.) в
`Угон`/`Без ТО`/`Сдан ГРЗ`/`Вывезена за рубеж`; пустая/некорректная `Дата ТО`; `Дата ТО` старше глубины
(относительно целевого года).
### Шаг 2. Владельцы
- Ключ: нормализованный `ИНН` (только цифры); если пуст — нормализованный `Владелец` (нижний регистр, без лишних пробелов).
- Физлицо: `Группа владельца` содержит (без учёта регистра) `физ`/`физическ`.
- Применить правило физлиц ≤ 3 ед. активной техники.
### Шаг 3. Целевые даты
- Стандартно: `Дата ТО + 1 год`.
- Категория А4 (кириллица `А4` и латиница `A4`): период 6 месяцев — 2 плановые даты в целевом году.
- Просроченная (`Дата ТО + период` < начала целевого года, но в пределах глубины): пометка «просроченная»,
  распределение на наименее загруженные месяцы целевого года (после расстановки регулярной техники).
### Шаг 4. Временная группировка внутри владельца
- Объединять в один визит (кластер) только единицы одного владельца с целевыми датами в пределах окна (≤ 30 дней).
- Целевая дата кластера — самая ранняя дата в кластере.
### Шаг 5. Производственный календарь
- `https://isdayoff.ru/api/getdata?year={YEAR}` с кэшем в `localStorage`.
- Fallback (офлайн/CORS): встроенный JSON 2025–2027 в репозитории; для неизвестных лет — Сб/Вс с уведомлением в UI.
- Рабочий день выезда: не выходной/праздник РФ, не приёмный день недели, не отпуск инспектора.
### Шаг 6. Распределение по дням, времени, географии
- Длительность визита: `ceil(машин / скорость_в_час)` с округлением до 30 минут (минимум 30 минут).
- Гео-кластеризация: из `Адрес владельца` регулярками извлекать населённый пункт / район / улицу; при совмещении
  визитов в один день приоритет владельцам из одной локации.
- Расстановка: пытаться на целевую дату; если день нерабочий или не хватает времени (обед, переезд между разными
  локациями) — сдвиг на ближайший свободный рабочий день ДО исходной даты (в пределах года; если до начала года
  места нет — вперёд). Первый визит — с начала рабочего дня (`с 9-00`), последующие — с учётом длительности
  предыдущего, переезда и обеда.

## 7. Предпросмотр и экспорт
- Вкладки: График ТО, Детализация, Исключённые записи, Сводка по месяцам + кнопка «Скачать Excel (.xlsx)».
- `.xlsx` (ExcelJS: автоширина, границы, форматирование), 4 листа:
  1. `График ТО`: `№ п/п`, `Наименование поселения (хозяйства, предприятия)` (из `Владелец`), `Дата проведения`
     (`ДД.ММ.ГГГГ`), `Время проведения` (`с ЧЧ-ММ`); сортировка по дате и времени; опционально примечание про физлиц.
  2. `Детализация`: дата, время (с–по), владелец, ИНН, адрес, кол-во техники, длительность, список гос. знаков/марок.
  3. `Исключенные записи`: исходные данные исключённой техники + `Причина исключения`.
  4. `Сводка и нагрузка`: загрузка по месяцам (выезды, машины) и применённые настройки.
